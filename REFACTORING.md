# Рефакторинг проекта

## Примененные принципы

- **KISS (Keep It Simple, Stupid)** - простые и понятные решения
- **DRY (Don't Repeat Yourself)** - устранение дублирования кода
- **YAGNI (You Ain't Gonna Need It)** - только необходимый функционал
- **SOLID** - разделение ответственности, независимость модулей

## Структура Backend

### До рефакторинга
- `main.py` - все роутеры, middleware, зависимости (615 строк)
- `crud.py` - все операции с БД (978 строк)
- Монолитные файлы без разделения ответственности

### После рефакторинга

#### Слои архитектуры:

1. **Routes (API endpoints)**
   - `routes/health.py` - проверка работоспособности
   - `routes/tasks.py` - работа с задачами и подзадачами
   - `routes/notes.py` - работа с заметками
   - `routes/stats.py` - статистика

2. **Services (Бизнес-логика)**
   - `services/task_service.py` - логика работы с задачами
   - `services/scheduler_service.py` - генерация задач по расписанию

3. **Repositories (Работа с БД)**
   - `repositories/user_repository.py` - пользователи
   - `repositories/task_repository.py` - задачи и подзадачи
   - `repositories/note_repository.py` - заметки
   - `repositories/stats_repository.py` - статистика

4. **Middleware**
   - `middleware/timezone_middleware.py` - сохранение часового пояса

5. **Dependencies**
   - `dependencies.py` - FastAPI зависимости (get_user_id, get_client_time)

6. **Main**
   - `main.py` - только инициализация приложения и планировщика (~150 строк)

## Структура Bot

### До рефакторинга
- `example_bot.py` - все команды, логика уведомлений (180 строк)
- `notifications.py` - уведомления
- `db_utils.py` - работа с БД

### После рефакторинга

1. **Handlers (Обработчики команд)**
   - `handlers/commands.py` - все команды бота

2. **Services (Бизнес-логика)**
   - `services/notification_service.py` - отправка уведомлений

3. **Repositories (Работа с БД)**
   - `repositories/user_repository.py` - пользователи

4. **Config**
   - `config.py` - конфигурация бота

5. **Main**
   - `example_bot.py` - только инициализация и регистрация обработчиков (~100 строк)

## Преимущества новой структуры

1. **Разделение ответственности** - каждый модуль отвечает за свою область
2. **Легкость тестирования** - можно тестировать каждый слой отдельно
3. **Масштабируемость** - легко добавлять новые функции
4. **Читаемость** - понятная структура, легко найти нужный код
5. **Переиспользование** - репозитории и сервисы можно использовать в разных местах
6. **Независимость** - модули слабо связаны между собой

## Миграция

Старые файлы (`crud.py`, `notifications.py`) оставлены для обратной совместимости, но рекомендуется использовать новую структуру.
