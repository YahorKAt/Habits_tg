# Логика отображения будущих задач

## 🎯 Краткое резюме

**Как это работает:**
- В БД хранится **одна запись задачи** (не создаются записи для каждого дня/недели/месяца)
- При запросе задач для конкретной даты система **вычисляет виртуально**, какие задачи должны показываться
- Для будущих дат задачи показываются автоматически со статусом "невыполнена"
- После выполнения задачи она автоматически появляется на следующий период

**Когда создаются/обновляются записи:**
- ✅ **Создание**: При создании задачи (`POST /task`) - создается одна запись
- ✅ **Обновление**: При изменении статуса (`PUT /task/{id}/completed`) - обновляется запись
- ❌ **НЕ создаются**: Записи для будущих дней/недель/месяцев НЕ создаются заранее

**Преимущества:**
- Экономия места в БД
- Гибкость (изменения применяются ко всем будущим повторениям)
- Простота управления

## 📋 Текущая реализация (Виртуальный подход)

### Как это работает сейчас:

**В базе данных хранится:**
- **Одна запись задачи** с полями:
  - `created_at` - дата создания задачи
  - `frequency` - частота повторения (daily/weekly/monthly)
  - `repeat_interval` - интервал повторения (каждые N дней/недель/месяцев)
  - `last_completed_date` - дата последнего выполнения
  - `completed` - текущий статус выполнения
  - `next_due_date` - следующая дата выполнения (вычисляется автоматически)

**В момент запроса задач для конкретной даты:**
1. Функция `list_tasks_with_subtasks()` получает все задачи пользователя из БД
2. Для каждой задачи вычисляется, должна ли она показываться для выбранной даты
3. Для будущих дат задачи показываются **виртуально** со статусом "невыполнена"

### Логика для разных типов задач:

#### 📅 Ежедневные задачи (daily):
- Показываются для **всех дней** начиная с `created_at`
- Для будущих дат всегда со статусом "невыполнена"
- После выполнения в день X, на следующий день (X+1) автоматически появляется новая задача со статусом "невыполнена"

#### 📆 Еженедельные задачи (weekly):
- Показываются для **всех недель** начиная с недели создания
- Для будущих недель всегда со статусом "невыполнена"
- После выполнения в неделю X:
  - В неделе X задача показывается со статусом "выполнена"
  - В следующих неделях (X+1, X+2, ...) задача автоматически появляется со статусом "невыполнена"

#### 📊 Месячные задачи (monthly):
- Показываются для **всех месяцев** начиная с месяца создания
- Для будущих месяцев всегда со статусом "невыполнена"
- После выполнения в месяц X:
  - В месяце X задача показывается со статусом "выполнена"
  - В следующих месяцах (X+1, X+2, ...) задача автоматически появляется со статусом "невыполнена"

## ✅ Преимущества текущего подхода:

1. **Экономия места в БД** - не создаются тысячи записей для будущих дней
2. **Гибкость** - можно изменить задачу, и изменения применятся ко всем будущим повторениям
3. **Простота** - не нужно управлять созданием/удалением записей
4. **Производительность** - один запрос к БД вместо тысяч

## ⚠️ Недостатки:

1. **Нет истории выполнения для будущих дат** - нельзя заранее отметить задачу как выполненную
2. **Сложная логика фильтрации** - нужно правильно вычислять, какие задачи показывать

## 🔄 Когда создаются/обновляются записи в БД:

### Создание задачи:
- **Момент**: При вызове API `POST /task`
- **Что происходит**: Создается одна запись в таблице `tasks` с полем `created_at = текущая дата`

### Обновление статуса:
- **Момент**: При вызове API `PUT /task/{id}/completed`
- **Что происходит**: 
  - Обновляется `completed = True/False`
  - Обновляется `last_completed_date = текущая дата` (если выполнена)
  - Обновляется `next_due_date = вычисляется автоматически` (если выполнена)
  - Обновляется `streak` (серия выполнений)

### Автоматический сброс ежедневных задач:
- **Момент**: При запросе задач для нового дня (после 00:00)
- **Что происходит**: 
  - В функции `list_tasks_with_subtasks()` проверяется, был ли выполнен сброс
  - Если `last_completed_date < сегодня`, то `completed = False`
  - Задача автоматически переносится на новый день

## 📝 Пример работы:

### Сценарий: Создание ежедневной задачи "Пить воду"

**День 1 (сегодня):**
1. Пользователь создает задачу "Пить воду" с frequency="daily"
2. В БД создается запись: `{id: 1, title: "Пить воду", frequency: "daily", created_at: "2024-01-15", completed: false}`
3. Задача отображается на сегодня со статусом "невыполнена"

**День 1 (вечер):**
1. Пользователь отмечает задачу как выполненную
2. В БД обновляется: `{completed: true, last_completed_date: "2024-01-15", next_due_date: "2024-01-16"}`

**День 2 (завтра, после 00:00):**
1. Пользователь открывает приложение
2. Функция `list_tasks_with_subtasks()` вызывается для даты "2024-01-16"
3. Система видит, что `last_completed_date = "2024-01-15" < "2024-01-16"`
4. Задача автоматически показывается для 16 января со статусом "невыполнена"
5. **В БД запись не создается** - используется та же запись, но виртуально показывается для нового дня

**День 2 (вечер):**
1. Пользователь снова отмечает задачу как выполненную
2. В БД обновляется: `{completed: true, last_completed_date: "2024-01-16", next_due_date: "2024-01-17"}`

**День 3 (послезавтра):**
1. Задача автоматически показывается для 17 января со статусом "невыполнена"
2. И так далее...

### Сценарий: Создание еженедельной задачи "Уборка"

**Неделя 1 (текущая неделя):**
1. Пользователь создает задачу "Уборка" с frequency="weekly"
2. В БД создается запись: `{id: 2, title: "Уборка", frequency: "weekly", created_at: "2024-01-15", completed: false}`
3. Задача отображается на текущей неделе со статусом "невыполнена"

**Неделя 1 (среда):**
1. Пользователь отмечает задачу как выполненную
2. В БД обновляется: `{completed: true, last_completed_date: "2024-01-17"}`

**Неделя 1 (пятница):**
1. Пользователь просматривает задачи на пятницу (та же неделя)
2. Задача показывается со статусом "выполнена" (так как выполнена в эту неделю)

**Неделя 2 (следующая неделя):**
1. Пользователь открывает приложение в понедельник следующей недели
2. Функция `list_tasks_with_subtasks()` вызывается для даты следующей недели
3. Система видит, что задача должна показываться для всех недель после создания
4. Задача автоматически показывается для недели 2 со статусом "невыполнена"
5. **В БД запись не создается** - используется та же запись, но виртуально показывается для новой недели

**Неделя 3, 4, 5...:**
1. Задача автоматически показывается для всех будущих недель со статусом "невыполнена"
2. После выполнения в неделю N, задача показывается:
   - В неделе N со статусом "выполнена"
   - В неделях N+1, N+2... со статусом "невыполнена"
